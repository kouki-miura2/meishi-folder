# Meishi-folder

もらった名刺を撮影し、AI で読み取った内容をクラウドで整理・検索する名刺管理アプリ。

## 総論

### 目的

名刺をもらった人が、名刺記載の項目、名刺をもらった場面（日付・場所・機会）、補足事項（関連プロジェクト・関連グループ・ハンドルネーム等）を、名刺の写真から記録・整理・検索できるようにする。

### 利用イメージ

- 設定
  - Google でログインし、ようこそ画面で氏名・所属を入力し、利用規約・プライバシーポリシーに同意して登録する。
- 登録
  - 名刺の表・裏を撮影する → AI が読み取った名刺記載項目を確認・訂正する → 保存する。
  - 同じ氏名の名刺が登録済みなら、上書きするか新規登録するかを選ぶ。
- 参照
  - 名刺一覧を五十音の見出しで探す。テキスト検索や、関連プロジェクト・関連グループで絞り込む。
  - 名刺詳細から電話・メール・地図を開く。
- 整理
  - 会社・団体、部署の表記ゆれを統合する。
  - 名刺の全データを CSV でダウンロードする。

### 提供形態

- Webアプリ（SPA）として提供する。主な利用環境はスマホのブラウザとする。PC のブラウザでも使える。
- スマホのホーム画面に追加でき、ホーム画面から開くとアドレスバーのない画面で起動する（PWA）。
- 公開範囲（PoC・一般公開など）と収益化の方針（未定）。
- 日本向けのサービスとする。日付の判定と日時の表示は日本時間（JST、UTC+9）とする（コード上は `packages/utils/src/date/zone.ts` の `TIME_ZONE_OFFSET_MINUTES`）。

### データの単位

- データは「ユーザー」単位で管理する。名刺・名刺写真・マスタ・プロフィールはすべてユーザーに属する。
- ユーザーは Google アカウント（`sub`）で識別する。1 つの Google アカウントが 1 ユーザーに対応する。
- 将来対応: ユーザー同士が相互認証すると、会社・団体どうし、会社・団体＋部署どうしを関連付けられる。関連付け後は、公開範囲が「会社」「部署」の名刺をお互いに参照できる。

### 用語

| 用語         | 意味                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| 名刺         | 1 人分の名刺の記録。名刺写真・名刺記載項目・場面・補足事項・公開範囲からなる                                      |
| 名刺写真     | 名刺の表・裏を撮影した画像                                                                                        |
| 名刺記載項目 | 名刺に印刷されている項目（氏名・会社・団体名・連絡先など）。AI 抽出の対象                                         |
| 場面         | 名刺をもらった取得日・取得場所・取得機会                                                                          |
| 補足事項     | 関連プロジェクト・関連グループ・ハンドルネーム・メモ                                                              |
| マスタ       | 会社・団体、部署、関連プロジェクト、関連グループ。ユーザーごとに持ち、他ユーザーとは共有しない                    |
| トピック     | 関連プロジェクトと関連グループの総称（GitHub のトピックのイメージ）                                               |
| 所属         | ユーザー自身の会社・団体（＋部署）                                                                                |
| 公開範囲     | 名刺を誰が参照できるか。個人・会社・部署のいずれか                                                                |
| 統合         | 同じ意味のマスタを 1 つにまとめること（名寄せ）                                                                   |
| 表記ゆれ     | 全角・半角や法人格の略記などの違いだけで、同じ意味のマスタが別々にできていること（「各論 > 表記ゆれの判定」参照） |
| 要確認       | AI 抽出の結果のうち、形式に不備があり確認を促す項目（「各論 > 要確認の判定」参照）                                |
| AI 抽出      | 名刺写真から名刺記載項目を AI で読み取ること                                                                      |
| 同一人物     | 保存しようとしている名刺と氏名が一致する登録済みの名刺                                                            |

### 権限

ロールは「登録したユーザー本人」と「他のユーザー」の 2 つ。

| 操作                                 | 本人 | 他のユーザー |
| ------------------------------------ | ---- | ------------ |
| 名刺の参照                           | ○    | ×            |
| 名刺の登録・変更・削除               | ○    | ×            |
| マスタの参照・追加・変更・削除・統合 | ○    | ×            |
| プロフィールの参照・変更、退会       | ○    | ×            |

- 権限は API で検証する。他ユーザーのデータは「存在しない」（404）として扱う。画面は本人のデータだけを表示する。
- 将来対応: 公開範囲が「会社」「部署」の名刺は、相互認証したユーザーも参照できる。

### 共通ルール

- 入力
  - 文字数・件数の上限は「参照 > リミット値」参照。上限は API でチェックする。メモは画面でも文字数を表示してチェックする。
  - 文字数は見た目の1文字を1文字と数える（全角・半角・絵文字とも1文字）。
  - 値の前後の空白は除き、空の値・重複する値は保存しない。
  - マスタの名称は同じユーザー内（部署は同じ会社・団体内、トピックは同じ種類内）で重複できない。
- 画面
  - 未ログインなら `/login` へ移動する。ログイン済みでプロフィール未登録なら `/welcome` へ移動する。ログイン後は元の画面に戻る。
  - 名刺一覧右上のアバターから、設定画面とログアウトを開く（デザインに入口がないため）。
  - 名刺詳細の「<」、名刺編集の保存・キャンセル、名刺登録の撮影のキャンセルは、戻り先の画面（一覧・詳細）が直前の履歴ならそこへ戻り（一覧の条件・スクロール位置を保つ）、そうでなければ（直接開いた・再読み込みした等）今の画面を戻り先に置き換える。同じ画面が履歴に 2 つ積まれないようにするため。
- 日付・日時の表示
  - 年を含める場合は `2026-09-29`（日時は `2026-09-29 10:21`）とする。
  - 年を表示しない形式は使わない。
- 同意
  - 利用規約・プライバシーポリシーへの同意の取得（未定）。ページができるまでは設定画面のリンクを無効表示にする。
- 削除
  - 名刺の削除と退会は確認ダイアログを経て行う。退会のダイアログでは、元に戻せないことと、必要なら先に CSV をダウンロードするよう案内する。そこで「削除する」を選ぶと最終確認のダイアログを出し、プロフィールの氏名が正しく入力されたときだけ退会できる。
- 同時更新
  - あと勝ちとする。
- オフライン
  - オフラインでは使えない。API の呼び出しはタイムアウト（「参照 > リミット値」参照）でエラーにする。

### 対象外

次の機能は提供しない。

- 他ユーザーとの名刺の共有（相互認証は将来対応）
- 他ユーザーのマスタとの統合（将来対応）
- 関連プロジェクト・関連グループの名称変更・削除・統合の画面
- 名刺写真を含むデータのエクスポート、データのインポート
- オフラインでの利用

## 各論

### 名刺

- 名刺ごとに名刺写真・名刺記載項目・場面・補足事項・公開範囲を記録する。

#### 項目

| 項目               | 備考                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| 名刺写真           | 任意。表・裏の 2 枚まで。「各論 > 名刺写真」参照                                                       |
| 氏名               | 任意。氏名・氏名カナ・ハンドルネームのいずれかは必須                                                   |
| 氏名カナ           | 任意                                                                                                   |
| 氏名ローマ字       | 任意                                                                                                   |
| 会社・団体名       | 任意。マスタ参照                                                                                       |
| 部署               | 任意、複数可。マスタ参照。部署があるときは会社・団体名が必須                                           |
| 役職・職種         | 任意、複数可                                                                                           |
| 携帯               | 任意                                                                                                   |
| メール・その他連絡 | 任意、複数可                                                                                           |
| URL                | 任意                                                                                                   |
| 事業所             | 任意、複数可。郵便番号・住所・電話・FAX（いずれも任意）                                                |
| 取得日             | 任意。`YYYY-MM-DD` の形式。登録時の初期値は今日                                                        |
| 取得場所・取得機会 | 任意                                                                                                   |
| 関連プロジェクト   | 任意、複数可。マスタ参照                                                                               |
| 関連グループ       | 任意、複数可。マスタ参照                                                                               |
| ハンドルネーム     | 任意                                                                                                   |
| メモ               | 任意。自由記述、改行可                                                                                 |
| 公開範囲           | 必須。個人・会社・部署のいずれか。登録時は「個人」。「会社」「部署」は相互認証（将来対応）まで選べない |
| 登録日時・更新日時 | 自動                                                                                                   |

- 名刺登録・名刺編集画面で、取得日・取得場所・取得機会が空の欄にフォーカスすると、この端末で前回保存した名刺の値を「前回：…」として表示し、タップで入力できる（同じ場で続けて何枚も入力するため）。前回値は空でなかった項目ごとに端末（localStorage）に保存し、ログアウト・退会で消去する。
- 件数・文字数の上限は「参照 > リミット値」参照。

#### 名刺一覧画面（1b, 1c）

- 表示する内容
  - 各行: 会社・団体名、部署、氏名、氏名カナまたはハンドルネーム、関連プロジェクト（赤のチップ）、関連グループ（青のチップ）。
  - ハンドルネームがあれば、氏名カナの代わりに「氏名／ハンドルネーム」と氏名と同じ大きさで表示する（ハンドルネームのほうが本人を思い出す手がかりになるため）。
  - 氏名順（初期値）: 五十音の見出しごとに並べ、見出しの索引で該当箇所へ移動できる（並び順は「各論 > 名刺 > 並び順・検索」参照）。
  - 会社名順: 見出しと索引なしで並べ、各行の会社・団体名を太字、氏名を標準の太さにする。
- 操作
  - 検索欄: 全項目のテキスト検索。入力が止まってから検索する（待ち時間は「参照 > リミット値」参照）。
  - フィルタ（ボトムシート）: タイトルと「クリア」の行は上、「N件を表示」は下に固定し、条件の部分だけをスクロールする。並び順「氏名順（初期値）/ 会社名順」、関連プロジェクト・関連グループの選択と、複数選択時の条件「いずれか（初期値）/ すべて」。条件に合う件数をシートに表示する。
  - 「クリア」は検索とフィルタの条件を消し、並び順はそのままにする。
  - 検索とフィルタの条件と並び順は URL（`?q=&topicIds=&match=&sort=company`）に残し、詳細から戻っても保たれる。
  - 名刺登録ボタン。

#### 名刺詳細画面（1h）

- 表示する内容
  - 名刺写真（タップで画像ビューワ）、全項目（名刺記載項目・場面・補足事項・公開範囲）。
  - 氏名カナ・氏名ローマ字は氏名のすぐ下に続けて表示する。ハンドルネーム・メモは値があるときだけ表示する（メモは改行もそのまま表示）。
  - URL はタップで新しいタブに開く。`https://` や `http://` で始まらなければ `https://` を付けて開く。
- 操作
  - 電話・メール・地図のボタン。電話は携帯、無ければ電話のある最初の事業所の電話。メールは先頭のメール。地図は住所のある最初の事業所の住所（Google マップで開く）。値が無いボタンは使えない。
  - 「•••」メニューは「この名刺を削除」だけ。

#### 名刺編集画面（1i）

- 全項目と公開範囲を変更する。名刺写真の回転・撮り直しもできる（「各論 > 名刺写真の変更」参照）。
- 公開範囲はボタングループ（個人・会社・部署）で選ぶ。「会社」「部署」は無効表示にする。
- 登録日時・更新日時を表示する。

#### 画像ビューワ（1j）

- 表・裏の切り替え、ピンチで拡大、回転（表示だけで保存しない）。縦型の名刺は縦長の枠で表示する。

#### 並び順・検索

- 並びのキー: 氏名カナ、無ければハンドルネーム、無ければ氏名。
- 名刺一覧（画面）: キーの先頭文字で五十音の見出し（ア・カ・サ・タ・ナ・ハ・マ・ヤ・ラ・ワ・A・#）に分け、見出しの中はキーの日本語の照合順（`localeCompare` の `ja`）。キーはひらがなをカタカナに、全角・半角を揃えて（NFKC）比べる。見出しは英数字なら A、カタカナ以外は #。キーが同じなら登録日時の順。
- 名刺一覧（画面・会社名順）: 会社・団体名、部署（複数ならその並び）、上記のキーの順。名称は読みを持たないので、書かれた文字のまま日本語の照合順（`localeCompare` の `ja`、NFKC で揃える）で比べる。会社・団体の無い名刺は最後。
- 名刺一覧（API）: キーの文字コード順、同じなら登録日時の順。画面はこれを上記の順に並べ直す。
- テキスト検索: 部分一致。英字の大文字・小文字は区別しない。対象は名刺の全テキスト項目（名刺記載項目・場面・ハンドルネーム・メモ）と、会社・団体・部署・関連プロジェクト・関連グループの名称。公開範囲は対象外。
- 関連プロジェクト・関連グループの絞り込み: 「すべて」は選んだトピックを全部持つ名刺、「いずれか」は 1 つ以上持つ名刺。画面の初期値は「いずれか」。API で `match` を省略したときは「すべて」。

#### 入力チェック

保存できない入力（画面で表示し、API は 400 を返す）:

- 氏名・氏名カナ・ハンドルネームがすべて空
- 会社・団体名が空で、部署がある
- 取得日が `YYYY-MM-DD` の形式でない
- 文字数・件数が上限を超える（「参照 > リミット値」参照。メモ以外は API のみ）
- 存在しない写真 ID（API のみ）
- 公開範囲が「会社」「部署」（相互認証（将来対応）まで、API のみ）

#### 登録・変更・削除

- 登録の流れは「各論 > 名刺登録」参照。
- 変更は名刺編集画面で行う。API は渡した項目だけを更新し、`null` で消去する。
- 削除は名刺詳細画面から確認して行い、名刺写真も削除する。

### 名刺登録

- 撮影／画像選択 → アップロード・AI 抽出 → 確認・訂正 → （同一人物の確認）→ 保存 の流れで名刺を登録する（1d〜1g）。
- 名刺の登録数が上限（「参照 > リミット値」参照）に達していたら、名刺登録画面を開いたときに撮影の前にその旨を表示し、名刺一覧に戻す（撮影・アップロードを無駄にしないため）。保存時に API が上限で拒否したとき（409）も同じ内容を表示する。同一人物の上書きは登録数を増やさないので対象外。

#### 撮影（1d）

- 表 → 裏の順に撮る。「写真を選択」でファイルからも選べる。裏面はスキップできる。カメラが使えない環境ではファイル選択だけになる。
- 撮影枠は横型（91:55）と縦型（55:91）を切り替えられる。初期値は横型で、表・裏は別々に切り替えられる（切り替えた向きは裏面にも引き継ぐ）。
- 撮影した写真は枠の範囲で切り取る（縦型の枠なら縦長の写真になる）。ファイルから選んだ写真は切り取らない。

#### アップロード・AI 抽出（1e）

- 写真を JPEG に縮小してアップロードし（長辺の大きさは「参照 > リミット値」参照）、名刺記載項目を AI で抽出する（「各論 > AI 抽出」参照）。
- 「スキップして手入力」で抽出を待たずに確認画面へ進める（アップロードは続け、保存時に完了を待つ）。
- アップロードに失敗したら撮影に戻る。抽出に失敗したら、空の確認画面に進む。

#### 確認・訂正（1f）

- 抽出した値を入力済みにし、ユーザーが訂正してから保存する。
- 表・裏の写真を縦横比を保ったサムネイルで表示する（縦型の名刺を切り取らない）。写真に向きの情報（EXIF）があれば、それに従って表示・縮小する。
- 撮影の角度で写真が 90° ずれたときは、サムネイルの回転ボタンで時計回りに 90° ずつ回転できる。回転した写真はその場でアップロードし直し、保存時にはその完了を待つ（AI 抽出はやり直さない）。
- 名刺記載項目・場面に加えて、補足事項（関連プロジェクト・関連グループ・ハンドルネーム・メモ）も入力できる（名刺編集と同じ）。
- 抽出できた項目数と「要確認」の項目（「各論 > 要確認の判定」参照）を表示する。
- 会社・団体と部署には、既存のマスタと一致するか（「既存マスタ」）、保存時に作られるか（「新規作成」）を表示する。

#### 同一人物の確認（1g）

- 保存前に、同一人物の名刺があれば候補を表示し、上書きするか新規登録するかをユーザーが選ぶ。
- 判定は、半角・全角のスペースを除いた氏名の一致だけ。同姓同名の可能性があるので、候補を見てユーザーが判断する。氏名が空なら判定しない。
- 上書きするのは名刺写真と名刺記載項目だけで、場面・補足事項・公開範囲は既存の値を保持する。差し替えられた元の写真は削除する。

### 名刺写真の変更

- 名刺編集画面で、登録済みの名刺の写真を回転・撮り直しできる。写真の変更は、編集内容と一緒に「保存」したときに反映する（キャンセルすれば元のまま）。

#### 回転

- 表・裏の写真を縦横比を保ったサムネイルで表示する。
- サムネイルの回転ボタンで時計回りに 90° ずつ回転できる。回転した写真はその場でアップロードし直し、保存時には完了を待つ（AI 抽出はやり直さない）。

#### 撮り直し

撮影 → アップロード・AI 抽出 → 差分の確認・訂正 → 保存 の流れで行う。

1. 撮影は名刺登録と同じ（表 → 裏、「写真を選択」、横型・縦型の枠）。裏面は「裏面は今のまま」で撮り直さずに今の裏面の写真を使える。
2. アップロード・AI 抽出は名刺登録と同じ（縮小、「スキップして手入力」）。アップロードに失敗したら撮影に戻る。
3. 抽出した値で名刺記載項目を上書きする（抽出で空だった項目も空にする）。場面・補足事項・メモ・公開範囲は変えない。
   - 保存済みの値から変わった名刺記載項目に「変更」と変更前の値を表示し、「戻す」で項目ごとに変更前の値に戻せる。変わった項目数と「要確認」の項目も表示する。
   - スキップしたとき、抽出に失敗したときは名刺記載項目を変えない（写真だけ差し替わる）。

#### 保存

- 保存すると、差し替えられた元の写真は削除する。保存しなかったときにアップロードした写真は、後で自動的に削除する（「各論 > 名刺写真」参照）。

### 名刺写真

- 登録フローでは先にアップロードして ID で参照する（AI 抽出と保存で同じ写真を 2 回送らない）。

#### 形式

- 形式は JPEG / PNG / WebP。1 枚の大きさの上限は「参照 > リミット値」参照。
- 形式はファイル先頭のバイト列で判定する（申告された種類は使わない）。

#### 向き

- 名刺には横型と縦型がある。向きはデータに持たず、写真の縦横（高さ ＞ 幅なら縦型）で判断する。
- 表示する画面（確認・訂正、名刺詳細、画像ビューワ）は、縦型なら縦長（55:91）の枠、横型なら横長（91:55）の枠で表示する。

#### 削除

- 名刺の削除時と、名刺の更新で写真が差し替えられた・消されたときに、元の写真も削除する（画面から写真が変わるのは同一人物の上書きと、名刺編集画面での回転・撮り直し）。
- 名刺に使われないままの写真（登録・編集を保存しなかった、回転する前の写真など）は、毎日決まった時刻に削除する。アップロードから一定時間内の写真は、保存の途中かもしれないので残す（時刻と時間は「参照 > リミット値」参照）。

### AI 抽出

- 名刺写真から名刺記載項目を読み取る。保存はしない。

#### モデル

- Workers AI の `@cf/meta/llama-3.2-11b-vision-instruct`（https://developers.cloudflare.com/ai/models/%40cf/meta/llama-3.2-11b-vision-instruct/ ）。
- 初回の利用前に、Cloudflare アカウントで Meta のライセンスに同意する必要がある。このモデルにプロンプト `agree` を 1 回送る（Workers AI の REST API など。アカウントごとに 1 回だけ）。

#### 抽出のしかた

- 表・裏を 1 枚ずつモデルに読ませ、表の値を優先して、表に無い項目を裏の値で補う（裏の英語表記のローマ字名など）。
- 氏名・氏名カナは、姓と名を分けてモデルに答えさせ、全角スペース 1 つでつなぐ（名刺によくある字間の空白「山 田　太 郎」を除くため）。姓と名の区切りが分からないときは、空白を除いた全体を 1 つにする。
- 氏名は印刷された漢字・かなのまま入れ、ローマ字にしない。ローマ字の氏名は氏名ローマ字に入れる。モデルが氏名に漢字・かなを 1 文字も含まない値を返したときは、氏名ローマ字に移す（氏名ローマ字が既にあればそちらを残す）。氏名は空にして、裏の値で補う。
- モデルには決まった形の JSON で答えさせる。応答が壊れていても失敗にせず、読めなかった項目は空のまま返す（ユーザーが確認画面で直す）。

### 要確認の判定

- AI は確信度を返さないため、確認画面では次の形式の不備を「要確認」として表示する（保存は妨げない）。

#### 条件

- 氏名が空
- 氏名カナにカタカナ以外が含まれる（空白・中黒・長音は可）
- 携帯・事業所の電話・FAX: 数字・空白・`()-`・先頭の `+` 以外が含まれる、または桁数が違う（050/070/080/090 で始まるものは 11 桁、ほかは 10 桁、`+` で始まる国際表記は 8〜15 桁）
- メール・URL・郵便番号（`123-4567` または `1234567`）の形式が不正

### マスタ

- 会社・団体、部署、関連プロジェクト、関連グループはユーザーごとのマスタで、他ユーザーとは共有しない。
- 名称の入力で参照し、一致するものが無ければ自動で作る。表記ゆれで同じ意味のマスタができたら、ユーザーが後から統合する。

#### 項目

| マスタ                         | 項目                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------- |
| 会社・団体                     | 会社・団体名                                                                                 |
| 部署                           | 会社・団体、部署名。会社・団体に属するサブマスタで、同じ名称でも会社・団体が異なれば別の部署 |
| 関連プロジェクト・関連グループ | 名称                                                                                         |

#### 会社・団体設定画面（1k, 1l）・部署設定画面（1m）

- 表示する内容
  - 会社・団体は名刺の枚数と部署の数、部署は名刺の枚数を表示する。
  - 表記ゆれの可能性があるマスタに「表記ゆれ?」を表示する。
- 操作
  - マスタの追加・名称変更・削除・統合。表記ゆれの可能性があるマスタはまとめて統合できる。
  - 統合では、残す名称を選ぶか、別の名称を入力する。
  - 部署設定画面は会社・団体設定画面のサブ画面で、その会社・団体の部署だけを扱う。

#### 一覧

- 並び順は名称の文字コード順（五十音順ではない）とする。会社・団体、部署、トピックとも同じ。

#### 登録・変更・削除

- 名称で受け取り、前後の空白を除いた完全一致で既存のマスタを探し、無ければ作る。
- 関連プロジェクト・関連グループは、名刺の登録・更新時に入力すれば作られる。
- 名刺やユーザーの所属で使われている会社・団体・部署は削除できず（409）、画面では統合を案内する。
- 会社・団体を削除すると、その会社・団体の部署も削除する。
- 統合元が空、または統合先を含むとき、別の会社・団体の部署と統合しようとしたとき、名称が空のときは 400 を返す（API のみ）。

#### 統合

1 回のトランザクションで行う。

- 会社・団体: 統合元を参照する名刺・ユーザーの所属・部署を統合先に付け替え、統合元を削除する。付け替えた部署と同じ名称の部署が統合先にあれば、その部署同士も統合する。
- 部署: 統合元を参照する名刺の部署・ユーザーの所属を統合先に付け替え（重複は除く）、統合元を削除する。同じ会社・団体の部署どうしに限る。

### 表記ゆれの判定

- 次の違いを除くと同じ名称になるマスタを、表記ゆれの可能性ありとする。

#### 除く違い

- 全角・半角（Unicode の NFKC 正規化）、英字の大文字・小文字
- 空白と記号（`/ ・ . , 、 。 | ( ) 「 」 [ ] -`）
- 法人格の略称と正式名称: (株)・㈱＝株式会社、(有)・㈲＝有限会社、(同)＝合同会社、(一社)＝一般社団法人、(一財)＝一般財団法人

### プロフィール

- ユーザー自身の氏名と所属を持つ。

#### 項目

| 項目     | 備考                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------- |
| 氏名     | 必須                                                                                                                 |
| 氏名カナ | 任意                                                                                                                 |
| 所属     | 任意、複数可。会社・団体（マスタ参照）＋部署（任意、マスタ参照）。同じ会社・団体の複数の部署は、所属を複数にして表す |

#### ようこそ画面（1a）

- 氏名、氏名カナ、所属（会社・団体と部署）を入力する。初回は Google アカウントの名前を氏名の初期値にする。
- 初回は「利用規約とプライバシーポリシーに同意する」にチェックするまで「はじめる」を押せない。各文書へのリンクは新しいタブで開く（入力中の内容を失わないため）。API も、現在の版（`TERMS_VERSION`、`packages/utils/src/terms/terms.ts`）への同意がない初回登録を 400 で拒否する。同意した版と日時を保存する。
- ログイン中の Google アカウント（メール）を表示する。
- 設定画面から開いたときは、保存したら設定画面に戻る。

### 設定

- 設定画面はデザインにないため、名刺一覧と同じトーンで、項目をまとまりごとの白い枠に並べる。

#### 画面

- プロフィール・所属（ようこそ画面を開く）、会社・団体の設定。
- 名刺データのダウンロード（「各論 > CSV 出力」参照）。
- アプリをインストール: ブラウザで開いているときだけ表示する（ホーム画面から開いたときは表示しない）。
  - 直接インストールできるブラウザ（Android の Chrome など）は、ブラウザのインストール確認を表示する。
  - iOS はスクリプトからインストールできないため、共有ボタンから「ホーム画面に追加」を選ぶ手順をダイアログで表示する。
  - どちらにも当てはまらないブラウザでは表示しない。
- ヘルプ、利用規約、プライバシーポリシー: 新しいタブで開く。利用規約・プライバシーポリシーはアプリ内のページ（`/terms`・`/privacy`）。ヘルプはページができるまで無効表示。
- 退会する（「各論 > 退会」参照）。

### CSV 出力

- 他のアプリへ移行できるよう、自分の名刺の全データを 1 つの CSV ファイルでダウンロードする。

#### 形式

- RFC 4180 に準拠する: 区切りはカンマ、行末は CRLF、1 行目は見出し。
- すべての値（見出しと空の値も）をダブルクォーテーションで括る。値の中の `"` は `""` と 2 つ重ねる。値の中の改行（メモ、複数値の区切り）はそのまま含める。
- 文字コードは UTF-8。Excel で開いても文字化けしないよう、先頭に BOM を付ける。
- ファイル名は `meishi-folder-YYYYMMDD.csv`（ダウンロードした日、日本時間）。

#### 行と列

- 1 行が名刺 1 枚。並び順は名刺一覧（API）と同じ（「各論 > 名刺 > 並び順・検索」参照）。
- 列（見出し）: ID、氏名、氏名カナ、氏名ローマ字、会社・団体、部署、役職、職種、携帯、メール、その他連絡、URL、事業所 n の郵便番号・住所・電話・FAX（`事業所1_郵便番号` など）、取得日、取得場所、取得機会、関連プロジェクト、関連グループ、ハンドルネーム、メモ、公開範囲（個人・会社・部署）、登録日時、更新日時（ISO 8601、UTC）。
  - 複数値（部署・役職・職種・メール・その他連絡・関連プロジェクト・関連グループ）は、1 つの値の中に改行区切りで並べる。
  - 事業所は、事業所の数が最も多い名刺に合わせて `事業所1_…`〜`事業所n_…` の列を並べる（名刺が無い・事業所が無いときも `事業所1_…` の列は出す）。
- 名刺写真は含めない。
- 値は保存したとおりに出力する（`=` や `+` で始まる値も変えない。移行先で値が変わらないことを優先する）。

### 退会

- ユーザーのすべてのデータを削除する。

#### 画面

- 設定画面の「退会する」から、確認ダイアログと氏名入力による最終確認を経て退会する（「総論 > 共通ルール」参照）。氏名は前後の空白を除いてプロフィールの氏名と一致したときだけ受け付ける。
- 退会すると、ログアウトしてログイン画面に戻る（自動ログインもしない）。
- 同じ Google アカウントで再びログインすると、データが空の状態でようこそ画面から始まる。

#### 削除するデータ

- その Google アカウント（`sub`）に紐づくプロフィール・所属、会社・団体、部署、関連プロジェクト・関連グループ、名刺、名刺写真。
- `users`・`user_affiliations`・`companies`・`departments`・`topics`・`cards`・`card_departments`・`card_topics` から、そのユーザーの行を 1 回のトランザクションで削除する。そのあと R2 の `<ユーザー>/` 以下の写真をすべて削除する。
- 写真の削除が途中で失敗しても、名刺に使われない写真として毎日の削除（「各論 > 名刺写真 > 削除」参照）で消える。
- プロフィール未登録でも成功する（何度呼んでも同じ結果）。

### データ保持・プライバシー

- データは退会するまで保持する。名刺に使われない写真は自動で削除する（「各論 > 名刺写真 > 削除」参照）。
- 全テーブルを所有者（`user_id`）で絞り込み、他ユーザーのデータは参照できない。
- 名刺写真は AI 抽出のために Workers AI に送る。
- 利用規約・プライバシーポリシーを `/terms`・`/privacy` で公開する（ログインしなくても読める）。本文は `apps/frontend/src/legal/documents.ts`。本文を変えたら `TERMS_VERSION` を改定日に更新する。
- 運営者名・お問い合わせ先は公開リポジトリにコミットしない。ローカルの `apps/frontend/.env.local` の `VITE_OPERATOR_NAME`・`VITE_CONTACT_EMAIL` から渡し、ビルド時にバンドルへ埋め込む（未設定なら「（運営者名）」「（お問い合わせ先）」と表示する）。
- 未定: 規約を改定したときに既存ユーザーへ再同意を求める仕組み。

### アーキテクチャ

- backend(API)
  - Hono（`apps/backend`、ランタイム非依存）on Cloudflare Workers（`apps/backend-worker`）。フロントエンドは Hono RPC で型付きに呼ぶ。
  - データ: Cloudflare D1（ユーザー・名刺・マスタ）
  - ファイルストレージ: Cloudflare R2（名刺写真）
  - AI 抽出: Workers AI（「各論 > AI 抽出」参照）
- frontend
  - Vue3 + Vuetify4 + vue-router + TanStack Query + Pinia の Webアプリ（SPA・PWA、`apps/frontend`）。
  - PWA は Web App Manifest（`public/manifest.webmanifest`）とアイコン（`public/icons/`、元の図案は `icon.svg`）だけで、Service Worker は持たない（API なしでは使えないため、オフライン用のキャッシュを持たない）。
- 配信
  - 画面と API を 1 つの Cloudflare Worker から同じオリジンで配信する。画面は `/`（存在しないパスは SPA の `index.html`）、API は `/api` 配下。
- 認証
  - Google でログインする。パスワードを預からず、ユーザーの多くが持つアカウントで始められるため。
  - フロントエンドが Google Identity Services で ID トークン（JWT）を取得し、`POST /session` で API に送る。API は Google の公開鍵で署名を検証し、発行者・宛先（OAuth クライアント ID）・有効期限を確認する。
  - 検証できたら、API が独自のセッションを発行する。Google の ID トークンは 1 時間で失効し、iOS では自動ログインも効きにくいため、ログインの頻度を 1 日 1 回程度に抑えるため。
    - セッションは `sub` と有効期限だけを持つ JWT（HS256、シークレット `SESSION_SECRET` で署名）。有効期間は「参照 > リミット値」参照。
    - Cookie `__Host-session` で渡す: `HttpOnly`（スクリプトから読めない）、`Secure`、`SameSite=Strict`、`Path=/`。以降の API はこの Cookie で認証する。
    - ステートレスで、サーバーに保存しない。そのため、期限前に個別に取り消すことはできない（全員を取り消すには `SESSION_SECRET` を変える）。端末を紛失したときなどは、最長で有効期間のあいだ使える。
    - CSRF: `SameSite=Strict` に加え、フォームから送れる形式の更新リクエストは、`Sec-Fetch-Site` または `Origin` が同じオリジンでなければ 403 で拒否する。
  - フロントエンドは、表示用のアカウント情報（メール・名前・画像）とセッションの有効期限を `localStorage` に保存し、期限が過ぎたらログイン画面へ移る。API が 401 を返したときもサインアウトしてログイン画面へ戻す。ログイン画面は Google の自動ログインを試す。
  - ログアウト（`DELETE /session`）で Cookie を消す。
  - OAuth クライアント ID は公開リポジトリにコミットしない（API はシークレット `GOOGLE_CLIENT_ID`、フロントエンドはローカルの `.env.local` の `VITE_GOOGLE_CLIENT_ID` から渡し、ビルド時にバンドルへ埋め込む）。

### データ仕様

仕様を満たす最小限のデータを保持する。導出できる値（名刺の枚数、部署の数など）は都度集計する。

- 各テーブルの `id` は `crypto.randomUUID()` で生成する（`users.id` は Google の `sub`）。
- 日時は ISO 8601（UTC）の文字列で持つ。
- 全テーブルを所有者（`user_id`）で絞り込む。他ユーザーのデータは「存在しない」（404）として扱う。
- マスタを参照しない複数値（役職、職種、メール、その他連絡、事業所）は JSON 列に持つ。
- テキスト検索は `LIKE`。件数が増えて遅くなったら全文検索（FTS5）を検討する。

#### Cloudflare R2

- オブジェクトキー: `<ユーザー ID>/<写真 ID>`
- 形式は JPEG / PNG / WebP（「各論 > 名刺写真 > 形式」参照）。アップロード日時は R2 のオブジェクトの `uploaded` を使う。
- 上書きはしない（回転・撮り直しは新しい写真としてアップロードする）。削除は「各論 > 名刺写真 > 削除」参照。

#### DBの外で管理するデータ

- **OAuth クライアント ID:** API は Workers のシークレット `GOOGLE_CLIENT_ID`、フロントエンドは `.env.local` の `VITE_GOOGLE_CLIENT_ID`（「参照 > アーキテクチャ」参照）。
- **セッション署名鍵:** Workers のシークレット `SESSION_SECRET`（32 文字以上のランダムな文字列）。変えると全員がログアウトする。
- **セッション:** ブラウザの Cookie `__Host-session`（HttpOnly）。表示用のアカウント情報と有効期限は `localStorage`（ログアウト・退会で消去）。

### API

パスはすべて `/api` の下（例: `GET /api/me`）。`/session` 以外はすべて認証（セッション Cookie）が必要。

| メソッド | パス                                | 内容                                                                                                                                               |
| -------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST     | `/session`                          | ログイン: `{ idToken }`（Google の ID トークン）を検証し、セッション Cookie を発行する。アカウント情報と有効期限を返す。無効なら 401               |
| DELETE   | `/session`                          | ログアウト: セッション Cookie を消す                                                                                                               |
| GET      | `/me`                               | 自分のプロフィール。未登録なら 404（ようこそ画面へ）                                                                                               |
| PUT      | `/me`                               | プロフィールの登録・更新（氏名、氏名カナ、所属 `[{companyName, departmentName?}]`、`agreedTermsVersion`。初回登録は現在の `TERMS_VERSION` が必須） |
| DELETE   | `/me`                               | 退会: 自分のすべてのデータを削除する（「各論 > 退会」参照）                                                                                        |
| GET      | `/companies`                        | 会社・団体の一覧（名刺の枚数・部署の数付き）                                                                                                       |
| POST     | `/companies`                        | 追加                                                                                                                                               |
| PATCH    | `/companies/:id`                    | 名称変更                                                                                                                                           |
| DELETE   | `/companies/:id`                    | 削除（その会社・団体の部署も削除。使用中なら 409）                                                                                                 |
| POST     | `/companies/:id/merge`              | `{ sourceIds }` を `:id` に統合                                                                                                                    |
| GET      | `/companies/:companyId/departments` | 部署の一覧（名刺の枚数付き）                                                                                                                       |
| POST     | `/companies/:companyId/departments` | 追加                                                                                                                                               |
| PATCH    | `/departments/:id`                  | 名称変更                                                                                                                                           |
| DELETE   | `/departments/:id`                  | 削除（使用中なら 409）                                                                                                                             |
| POST     | `/departments/:id/merge`            | `{ sourceIds }` を `:id` に統合（同じ会社・団体の部署に限る）                                                                                      |
| GET      | `/topics?kind=`                     | 関連プロジェクト・関連グループの一覧。`kind` は `project` / `group`、省略すると両方                                                                |
| POST     | `/images`                           | 名刺写真（multipart の `file`）をアップロードし `{ id }` を返す                                                                                    |
| GET      | `/images/:id`                       | 名刺写真を返す                                                                                                                                     |
| POST     | `/cards/extract`                    | `{ frontImageId, backImageId? }` から名刺記載項目を抽出する（保存しない）。写真が無ければ 404                                                      |
| GET      | `/cards/export`                     | 名刺の全データを CSV（`text/csv`）で返す（「各論 > CSV 出力」参照）                                                                                |
| GET      | `/cards/candidates?name=`           | 同一人物の候補（「各論 > 名刺登録 > 同一人物の確認」参照）                                                                                         |
| GET      | `/cards?q=&topicIds=&match=`        | 名刺の一覧。`q` はテキスト検索、`topicIds` はカンマ区切り、`match` は `all`（既定）/ `any`（「各論 > 名刺 > 並び順・検索」参照）                   |
| GET      | `/cards/:id`                        | 名刺の詳細                                                                                                                                         |
| POST     | `/cards`                            | 登録（会社・団体、部署、トピックは名称で渡す。公開範囲は常に「個人」。登録数が上限なら 409）                                                       |
| PATCH    | `/cards/:id`                        | 更新（渡した項目だけ、`null` で消去）。同一人物の上書きでは名刺写真と名刺記載項目だけを渡す。差し替えた写真は削除                                  |
| DELETE   | `/cards/:id`                        | 削除（写真も削除）                                                                                                                                 |

### エラー

応答の本文は `{ "error": "<メッセージ>" }`。ただし、入力の形（型・必須・上限）が不正な 400 は、検証ライブラリ（zod）の結果をそのまま返す: `{ "success": false, "error": { "name": "ZodError", "message": "<問題点の一覧（JSON 文字列）>" } }`。

| ステータス | 条件                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------- |
| 400        | 入力の形が不正、または入力チェックに反する（「各論 > 名刺 > 入力チェック」「各論 > マスタ」参照） |
| 401        | 認証なし、またはセッション・ID トークンが無効                                                     |
| 403        | 別のサイトから送られた更新リクエスト（CSRF 対策）                                                 |
| 404        | 対象が無い（他ユーザーのデータを含む）                                                            |
| 409        | マスタの名称の重複、使用中のマスタの削除、名刺の登録数が上限                                      |
| 413        | リクエストの本文が上限を超える（「参照 > リミット値」参照）                                       |

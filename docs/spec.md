# Meishi-folder 仕様

## 1. 総論

### 目的

もらった名刺の写真を撮り、クラウドでその情報を管理する。名刺記載の項目、名刺をもらった場面（日付・場所・機会）、補足事項（関連プロジェクト・関連グループ・ハンドルネーム等）を記録・整理・検索するツール。名刺ごとに公開範囲を設定できる。

### 認証

- Google でログインする。ユーザーは Google アカウント（`sub`）で識別する。

### アクセス権

- 当初は、全データを登録したユーザー本人だけが参照・追加・変更・削除できる。
- 将来対応: ユーザー同士が相互認証すると、会社・団体どうし、会社・団体＋部署どうしを関連付けられる。関連付け後は、公開範囲が「会社」「部署」の名刺をお互いに参照できる。

### マスタ

- 会社・団体、部署、関連プロジェクト、関連グループはユーザーごとのマスタで、他ユーザーとは共有しない。
- マスタは名称の入力で参照し、一致するものが無ければ自動で作る。表記ゆれで同じ意味のマスタができたら、ユーザーが後から統合（名寄せ）する。
- 将来対応: 自分のマスタと他ユーザーのマスタを統合できる。

## 2. 各論

### 2.1 データ

ユーザー:

- 氏名(1)、氏名カナ(0..1)
- 所属(0..N): 会社・団体(1・マスタ参照) ＋ 部署(0..1・マスタ参照)。同じ会社・団体の複数の部署は、所属を複数にして表す

会社・団体: 会社・団体名

部署: 会社・団体(1)、部署名。部署は会社・団体に属するサブマスタで、同じ名称でも会社・団体が異なれば別の部署

関連プロジェクト・関連グループ: 名称（GitHub のトピックのイメージ）

名刺:

- 名刺写真(0..2) ※表・裏
- 名刺記載項目
  - 氏名(0..1)、氏名カナ(0..1)、氏名ローマ字(0..1)、会社・団体名(0..1・マスタ参照)、部署(0..N・マスタ参照)、役職(0..N)、職種(0..N)
  - 携帯(0..1)、メール(0..N)、その他連絡(0..N)、URL(0..1)
  - 事業所(0..N): 郵便番号(0..1)、住所(0..1)、電話(0..1)、FAX(0..1)
- 場面: 取得日(0..1)、取得場所(0..1)、取得機会(0..1)
- 補足事項: 関連プロジェクト(0..N・マスタ参照)、関連グループ(0..N・マスタ参照)、ハンドルネーム(0..1)、メモ(0..1・自由記述、改行可、1000 字まで)
- 公開範囲: 個人・会社・部署のいずれか。登録時は「個人」
- 登録ユーザー、登録日時、更新日時

### 2.2 画面

画面の一覧とルートは [4.1 画面一覧](#41-画面一覧) を参照。

- 共通
  - 未ログインなら `/login` へ。ログイン済みでプロフィール未登録なら `/welcome` へ。ログイン後は元の画面に戻る。
  - 一覧右上のアバターから、プロフィール・所属の変更、会社・団体の設定、ログアウトを開く（デザインに入口がないため）。
- ようこそ画面（1a）
  - 氏名、氏名カナ、所属（会社・団体と部署）を入力する。初回は Google アカウントの名前を氏名の初期値にする。
  - ログイン中の Google アカウント（メール）を表示する。
- 名刺一覧画面（1b, 1c）
  - 一覧の各行: 会社・団体名、部署、氏名、氏名カナまたはハンドルネーム、関連プロジェクト（赤のチップ）、関連グループ（青のチップ）。
  - 五十音の見出しごとに並べ、見出しの索引で該当箇所へ移動できる（並び順は [3.6 並び順・検索](#36-並び順検索)）。
  - 検索欄: 全項目のテキスト検索。入力が 300ms 止まってから検索する。
  - フィルタ（ボトムシート）: 関連プロジェクト・関連グループの選択と、複数選択時の条件「いずれか（初期値）/ すべて」。条件に合う件数をシートに表示する。
  - 検索とフィルタの条件は URL（`?q=&topicIds=&match=`）に残し、詳細から戻っても保たれる。
  - 名刺登録ボタン。
- 名刺登録画面（1d〜1g）: 流れは [2.3 名刺登録](#23-名刺登録) を参照。
- 名刺詳細画面（1h）
  - 名刺写真（タップで画像ビューワ。縦型の名刺は縦長の枠で表示、[3.3 名刺写真](#33-名刺写真)）、全項目（名刺記載項目・場面・補足事項・公開範囲）。
  - 氏名カナ・氏名ローマ字は氏名のすぐ下に続けて表示する。ハンドルネーム・メモは値があるときだけ表示する（メモは改行もそのまま表示）。
  - 電話・メール・地図のボタン。電話は携帯、無ければ電話のある最初の事業所の電話。メールは先頭のメール。地図は住所のある最初の事業所の住所（Google マップで開く）。値が無いボタンは使えない。
  - 「•••」メニューは「この名刺を削除」だけ。削除は確認してから行い、写真も削除する。
- 名刺編集画面（1i）: 全項目と公開範囲を変更する。名刺写真の回転・撮り直しもできる（[2.4 名刺写真の変更](#24-名刺写真の変更)）。
  - 公開範囲はボタングループ（個人・会社・部署）で選ぶ。「会社」「部署」は相互認証（将来対応）まで選べない（無効表示）。
- 画像ビューワ（1j）: 表・裏の切り替え、ピンチで拡大、回転（表示だけで保存しない）。縦型の名刺は縦長の枠で表示する。
- 会社・団体設定画面（1k, 1l）・部署設定画面（1m）
  - マスタの追加・名称変更・削除・統合。会社・団体は名刺の枚数と部署の数、部署は名刺の枚数を表示する。
  - 表記ゆれの可能性があるマスタに「表記ゆれ?」を表示し、まとめて統合できる（判定は [3.7 表記ゆれの判定](#37-表記ゆれの判定)）。
  - 名刺やユーザーの所属で使われているマスタは削除できず、統合を案内する。
  - 統合では、残す名称を選ぶか、別の名称を入力する。統合の内容は [3.5 マスタ](#35-マスタ) を参照。
  - 部署設定画面は会社・団体設定画面のサブ画面で、その会社・団体の部署だけを扱う。

### 2.3 名刺登録

流れ: 撮影／画像選択 → アップロード・AI 抽出 → 確認・訂正 → （同一人物の確認）→ 保存

1. 撮影（1d）: 表 → 裏の順に撮る。「写真を選択」でファイルからも選べる。裏面はスキップできる。カメラが使えない環境ではファイル選択だけになる。
   - 撮影枠は横型（91:55）と縦型（55:91）を切り替えられる。初期値は横型で、表・裏は別々に切り替えられる（切り替えた向きは裏面にも引き継ぐ）。
   - 撮影した写真は枠の範囲で切り取る（縦型の枠なら縦長の写真になる）。ファイルから選んだ写真は切り取らない。
2. アップロード・AI 抽出（1e）: 写真を長辺 1600px の JPEG に縮小してアップロードし、名刺記載項目を AI で抽出する（[3.4 AI 抽出](#34-ai-抽出)）。
   - 「スキップして手入力」で抽出を待たずに確認画面へ進める（アップロードは続け、保存時に完了を待つ）。
   - アップロードに失敗したら撮影に戻る。抽出に失敗したら、空の確認画面に進む。
3. 確認・訂正（1f）: 抽出した値を入力済みにし、ユーザーが訂正してから保存する。
   - 表・裏の写真を縦横比を保ったサムネイルで表示する（縦型の名刺を切り取らない）。写真に向きの情報（EXIF）があれば、それに従って表示・縮小する。
   - 撮影の角度で写真が 90° ずれたときは、サムネイルの回転ボタンで時計回りに 90° ずつ回転できる。回転した写真はその場でアップロードし直し、保存時にはその完了を待つ（AI 抽出はやり直さない）。
   - 名刺記載項目・場面に加えて、メモも入力できる。
   - 抽出できた項目数と「要確認」の項目（[3.8 要確認の判定](#38-要確認の判定)）を表示する。
   - 会社・団体と部署には、既存のマスタと一致するか（「既存マスタ」）、保存時に作られるか（「新規作成」）を表示する。
   - 取得日の初期値は今日。
4. 同一人物の確認（1g）: 保存前に、氏名が一致する登録済みの名刺があれば候補を表示し、上書きするか新規登録するかをユーザーが選ぶ。
   - 判定は氏名の一致だけ（空白は無視、[3.6 並び順・検索](#36-並び順検索)）。同姓同名の可能性があるので、候補を見てユーザーが判断する。氏名が空なら判定しない。
   - 上書きするのは名刺写真と名刺記載項目だけで、場面・補足事項・公開範囲は既存の値を保持する。差し替えられた元の写真は削除する。

### 2.4 名刺写真の変更

名刺編集画面で、登録済みの名刺の写真を回転・撮り直しできる。写真の変更は、編集内容と一緒に「保存」したときに反映する（キャンセルすれば元のまま）。

- 表・裏の写真を縦横比を保ったサムネイルで表示する。
- 回転: サムネイルの回転ボタンで時計回りに 90° ずつ回転できる。回転した写真はその場でアップロードし直し、保存時には完了を待つ（AI 抽出はやり直さない）。
- 撮り直し: 流れは 撮影 → アップロード・AI 抽出 → 差分の確認・訂正 → 保存。
  1. 撮影は名刺登録と同じ（表 → 裏、「写真を選択」、横型・縦型の枠）。裏面は「裏面は今のまま」で撮り直さずに今の裏面の写真を使える。
  2. アップロード・AI 抽出は名刺登録と同じ（長辺 1600px の JPEG、「スキップして手入力」）。アップロードに失敗したら撮影に戻る。
  3. 抽出した値で名刺記載項目を上書きする（抽出で空だった項目も空にする）。場面・補足事項・メモ・公開範囲は変えない。
     - 保存済みの値から変わった名刺記載項目に「変更」と変更前の値を表示し、「戻す」で項目ごとに変更前の値に戻せる。変わった項目数と「要確認」の項目も表示する。
     - スキップしたとき、抽出に失敗したときは名刺記載項目を変えない（写真だけ差し替わる）。
- 保存すると、差し替えられた元の写真は削除する。保存しなかったときにアップロードした写真は、後で自動的に削除する（[3.3 名刺写真](#33-名刺写真)）。

## 3. 詳細

### 3.1 システム構成

- 1 つの Cloudflare Worker（https://meishi-folder.miu-soft.workers.dev ）で、フロントエンドと API を同じオリジンから配信する。API は `/api` の下、それ以外のパスはフロントエンド（存在しないパスは SPA の `index.html`）。
- フロントエンド: Vue 3 + Vuetify 4 + vue-router + TanStack Query + Pinia（`apps/frontend`）。
- API: Hono（`apps/backend`、ランタイム非依存）を Cloudflare Workers で動かす（`apps/backend-worker`）。フロントエンドは Hono RPC で型付きに呼ぶ。
- データ: ユーザー・名刺・マスタは D1、名刺写真は R2、名刺記載項目の抽出は Workers AI。
- 画面デザイン
  - Claude Design で作成: https://claude.ai/artifact/QRofMAZDkyMytHHhwciqRq
  - 画面 ID（1a〜1m）はこのデザインの番号。画面は実装済みで、今の見た目の基準は実装（色は `apps/frontend/src/plugins/vuetify.ts` のテーマ）。
  - スマホ（幅 390px）が基準。PC では同じレイアウトを中央寄せ（最大幅 480px）で表示する。
  - 色はデザインどおり（紙のオフホワイト・墨色、意味色はプロジェクト＝赤・グループ＝青・AI 要確認＝黄の 3 つだけ）。
  - フォント: 本文は Noto Sans JP（デザインの Zen Kaku Gothic New は使わない）、数字・英字（日付・件数・メール等）は IBM Plex Mono。

### 3.2 認証

- フロントエンドが Google Identity Services で ID トークン（JWT）を取得し、`Authorization: Bearer <token>` で API に送る。独自のセッションは持たない。
- API は Google の公開鍵で署名を検証し、発行者・宛先（OAuth クライアント ID）・有効期限を確認する。
- ID トークンは 1 時間で失効する。失効の 60 秒前からそのトークンは送らない。API が 401 を返したらサインアウトしてログイン画面へ戻す。ログイン画面は Google の自動ログインを試すので、再ログインの手間はほぼない。
- OAuth クライアント ID は公開リポジトリにコミットしない（API はシークレット `GOOGLE_CLIENT_ID`、フロントエンドはローカルの `.env.local` の `VITE_GOOGLE_CLIENT_ID` から渡し、ビルド時にバンドルへ埋め込む）。

### 3.3 名刺写真

- 登録フローでは先にアップロードして ID で参照する（AI 抽出と保存で同じ写真を 2 回送らない）。
- 形式は JPEG / PNG / WebP、1 枚 5MB まで。形式はファイル先頭のバイト列で判定する（申告された種類は使わない）。R2 に `<ユーザー>/<写真 ID>` のキーで保存する。
- 名刺には横型と縦型がある。向きはデータに持たず、写真の縦横（高さ ＞ 幅なら縦型）で判断する。表示する画面（確認・訂正、名刺詳細、画像ビューワ）は、縦型なら縦長（55:91）の枠、横型なら横長（91:55）の枠で表示する。
- 名刺の削除時と、名刺の更新で写真が差し替えられた・消されたときに、元の写真も削除する（画面から写真が変わるのは同一人物の上書きと、名刺編集画面での回転・撮り直し）。
- 名刺に使われないままの写真（登録・編集を保存しなかった、回転する前の写真など）は、毎日 3:00（日本時間、Cron Trigger）に削除する。アップロードから 24 時間以内の写真は、保存の途中かもしれないので残す。

### 3.4 AI 抽出

- モデル: Workers AI の `@cf/meta/llama-3.2-11b-vision-instruct`（https://developers.cloudflare.com/ai/models/%40cf/meta/llama-3.2-11b-vision-instruct/ ）。
- 初回の利用前に、Cloudflare アカウントで Meta のライセンスに同意する必要がある。このモデルにプロンプト `agree` を 1 回送る（Workers AI の REST API など。アカウントごとに 1 回だけ）。
- 表・裏を 1 枚ずつモデルに読ませ、表の値を優先して、表に無い項目を裏の値で補う（裏の英語表記のローマ字名など）。
- モデルには決まった形の JSON で答えさせる。応答が壊れていても失敗にせず、読めなかった項目は空のまま返す（ユーザーが確認画面で直す）。

### 3.5 マスタ

- 名称で受け取り、前後の空白を除いた完全一致で既存のマスタを探し、無ければ作る。
- 名称は同じユーザー内（部署は同じ会社・団体内、トピックは同じ種類内）で重複できない。
- 関連プロジェクト・関連グループは、名刺の登録・更新時に入力すれば作られる。名称変更・削除・統合の画面はない。
- 名刺やユーザーの所属で使われている会社・団体・部署は削除できない（409）。会社・団体を削除すると、その会社・団体の部署も削除する。
- 統合（1 回のトランザクションで行う）:
  - 会社・団体: 統合元を参照する名刺・ユーザーの所属・部署を統合先に付け替え、統合元を削除する。付け替えた部署と同じ名称の部署が統合先にあれば、その部署同士も統合する。
  - 部署: 統合元を参照する名刺の部署・ユーザーの所属を統合先に付け替え（重複は除く）、統合元を削除する。同じ会社・団体の部署どうしに限る。

### 3.6 並び順・検索

- 並びのキー: 氏名カナ、無ければハンドルネーム、無ければ氏名。
- 名刺一覧（画面）: キーの先頭文字で五十音の見出し（ア・カ・サ・タ・ナ・ハ・マ・ヤ・ラ・ワ・A・#）に分け、見出しの中はキーの日本語の照合順（`localeCompare` の `ja`）。キーはひらがなをカタカナに、全角・半角を揃えて（NFKC）比べる。見出しは英数字なら A、カタカナ以外は #。キーが同じなら登録日時の順。
- 名刺一覧（API）: キーの文字コード順、同じなら登録日時の順。画面はこれを上記の順に並べ直す。
- マスタの一覧（会社・団体、部署、トピック）: 名称の文字コード順（五十音順ではない）。
- テキスト検索: 部分一致。英字の大文字・小文字は区別しない。対象は名刺の全テキスト項目（名刺記載項目・場面・ハンドルネーム・メモ）と、会社・団体・部署・関連プロジェクト・関連グループの名称。公開範囲は対象外。
- 関連プロジェクト・関連グループの絞り込み: 「すべて」は選んだトピックを全部持つ名刺、「いずれか」は 1 つ以上持つ名刺。画面の初期値は「いずれか」。API で `match` を省略したときは「すべて」。
- 同一人物の候補: 半角・全角のスペースを除いた氏名が一致する名刺。

### 3.7 表記ゆれの判定

次の違いを除くと同じ名称になるマスタを、表記ゆれの可能性ありとする。

- 全角・半角（Unicode の NFKC 正規化）、英字の大文字・小文字
- 空白と記号（`/ ・ . , 、 。 | ( ) 「 」 [ ] -`）
- 法人格の略称と正式名称: (株)・㈱＝株式会社、(有)・㈲＝有限会社、(同)＝合同会社、(一社)＝一般社団法人、(一財)＝一般財団法人

### 3.8 要確認の判定

AI は確信度を返さないため、確認画面では次の形式の不備を「要確認」として表示する（保存は妨げない）。

- 氏名が空
- 氏名カナにカタカナ以外が含まれる（空白・中黒・長音は可）
- 携帯・事業所の電話・FAX: 数字・空白・`()-`・先頭の `+` 以外が含まれる、または桁数が違う（050/070/080/090 で始まるものは 11 桁、ほかは 10 桁、`+` で始まる国際表記は 8〜15 桁）
- メール・URL・郵便番号（`123-4567` または `1234567`）の形式が不正

### 3.9 入力チェック

保存できない入力（画面で表示し、API は 400 を返す）:

- 氏名・氏名カナ・ハンドルネームがすべて空
- 会社・団体名が空で、部署がある
- 取得日が `YYYY-MM-DD` の形式でない
- 存在しない写真 ID（API のみ）
- 統合元が空、または統合先を含む。別の会社・団体の部署との統合（API のみ）
- マスタの名称が空（API のみ）
- 公開範囲が「会社」「部署」（相互認証（将来対応）まで、API のみ）

入力の上限（API）: リクエストの本文は 10MB、文字列は 1000 字、複数値（役職・メール等）は各 50 件、事業所・プロフィールの所属は各 20 件、統合元は 100 件まで。値の前後の空白は除き、空の値・重複する値は保存しない。

### 4.2 データモデル（D1）

```text
users             id(=Google sub) PK, name, name_kana, created_at, updated_at
user_affiliations user_id, company_id, department_id(NULL可)
companies         id PK, user_id, name              UNIQUE(user_id, name)
departments       id PK, user_id, company_id, name  UNIQUE(company_id, name)
topics            id PK, user_id, kind('project'|'group'), name  UNIQUE(user_id, kind, name)
cards             id PK, user_id,
                  name, name_kana, name_romaji, company_id(NULL可),
                  titles JSON, job_types JSON, mobile, emails JSON, other_contacts JSON, url,
                  offices JSON  -- [{postalCode, address, tel, fax}]
                  met_on, met_at, met_occasion, handle_name, memo,
                  front_image_id, back_image_id, visibility('private'|'company'|'department'),
                  created_at, updated_at
card_departments  card_id, department_id            -- 部署(0..N)
card_topics       card_id, topic_id                 -- 関連プロジェクト・グループ(0..N)
```

- 全テーブルを所有者（`user_id`）で絞り込む。他ユーザーのデータは「存在しない」（404）として扱う。
- マスタを参照しない複数値（役職、職種、メール、その他連絡、事業所）は JSON 列に持つ。
- テキスト検索は `LIKE`。件数が増えて遅くなったら全文検索（FTS5）を検討する。

### 4.3 API

パスはすべて `/api` の下（例: `GET /api/me`）。すべて認証が必要。

| メソッド | パス                                | 内容                                                                                                                |
| -------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET      | `/me`                               | 自分のプロフィール。未登録なら 404（ようこそ画面へ）                                                                |
| PUT      | `/me`                               | プロフィールの登録・更新（氏名、氏名カナ、所属 `[{companyName, departmentName?}]`）                                 |
| GET      | `/companies`                        | 会社・団体の一覧（名刺の枚数・部署の数付き）                                                                        |
| POST     | `/companies`                        | 追加                                                                                                                |
| PATCH    | `/companies/:id`                    | 名称変更                                                                                                            |
| DELETE   | `/companies/:id`                    | 削除（その会社・団体の部署も削除。使用中なら 409）                                                                  |
| POST     | `/companies/:id/merge`              | `{ sourceIds }` を `:id` に統合                                                                                     |
| GET      | `/companies/:companyId/departments` | 部署の一覧（名刺の枚数付き）                                                                                        |
| POST     | `/companies/:companyId/departments` | 追加                                                                                                                |
| PATCH    | `/departments/:id`                  | 名称変更                                                                                                            |
| DELETE   | `/departments/:id`                  | 削除（使用中なら 409）                                                                                              |
| POST     | `/departments/:id/merge`            | `{ sourceIds }` を `:id` に統合（同じ会社・団体の部署に限る）                                                       |
| GET      | `/topics?kind=`                     | 関連プロジェクト・関連グループの一覧。`kind` は `project` / `group`、省略すると両方                                 |
| POST     | `/images`                           | 名刺写真（multipart の `file`）をアップロードし `{ id }` を返す                                                     |
| GET      | `/images/:id`                       | 名刺写真を返す                                                                                                      |
| POST     | `/cards/extract`                    | `{ frontImageId, backImageId? }` から名刺記載項目を抽出する（保存しない）。写真が無ければ 404                       |
| GET      | `/cards/candidates?name=`           | 同一人物の候補（[3.6](#36-並び順検索)）                                                                             |
| GET      | `/cards?q=&topicIds=&match=`        | 名刺の一覧。`q` はテキスト検索、`topicIds` はカンマ区切り、`match` は `all`（既定）/ `any`（[3.6](#36-並び順検索)） |
| GET      | `/cards/:id`                        | 名刺の詳細                                                                                                          |
| POST     | `/cards`                            | 登録（会社・団体、部署、トピックは名称で渡す。公開範囲は常に「個人」）                                              |
| PATCH    | `/cards/:id`                        | 更新（渡した項目だけ、`null` で消去）。同一人物の上書きでは名刺写真と名刺記載項目だけを渡す。差し替えた写真は削除   |
| DELETE   | `/cards/:id`                        | 削除（写真も削除）                                                                                                  |

### 4.4 エラー

応答の本文は `{ "error": "<メッセージ>" }`。ただし、入力の形（型・必須・上限）が不正な 400 は、検証ライブラリ（zod）の結果をそのまま返す: `{ "success": false, "error": { "name": "ZodError", "message": "<問題点の一覧（JSON 文字列）>" } }`。

| ステータス | 条件                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 400        | 入力の形が不正、または [3.9 入力チェック](#39-入力チェック) に反する |
| 401        | 認証なし、または ID トークンが無効                                   |
| 404        | 対象が無い（他ユーザーのデータを含む）                               |
| 409        | マスタの名称の重複、使用中のマスタの削除                             |
| 413        | リクエストの本文が 10MB を超える                                     |
